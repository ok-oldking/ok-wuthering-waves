# ADR 0001：Mac 原生 16:10 内容帧与显式视觉坐标适配

状态：accepted（2026-09-05，用户批准 contributor 本地集成分支实施；不代表 upstream 已接受）

## 背景与决定

用户提供的官方 Mac 客户端分辨率菜单包含 1512×945、1352×845、1280×800，均为 16:10；用户确认游戏自身不能切换比例。一次公开 AXSize 可写性真机检查失败。继续强制 1920×1080 会阻断原生客户端验收。

本 ADR 是本次坐标/验收合同变更的权威记录，配套 ok-script 同名 ADR 引用本记录。允许 Mac 原生 16:10，保留已有 16:9 与 Windows 行为。1280×800 为新增菜单目标，实际验收必须记录新 ScreenCaptureKit 内容帧尺寸，不能用菜单值、截图附件尺寸、SCWindow 外框或固定 Retina 倍数代替。先前 1512×982 不是严格 16:10，不自动归入已支持比例。

不拉伸整帧、不裁去游戏内容伪造 16:9、不修改系统显示、游戏 INI 或继续强制窗口尺寸。图像保持原生 BGR 内容帧；视觉参考坐标只能通过显式、可测的缩放及边缘/中心锚点转换。不能假定所有页面采用同一布局缩放；OCR/模板返回的真实帧坐标不得二次转换。沿用已有框架 helper，必要通用几何能力属于 ok-script，游戏布局选择及任务接入属于 OK-WW。

## 规范影响

对 `MACOS_ENGINEERING_CONSTRAINTS.md` 的目标基线、2/16/19 节，以及实施计划 Stage D/F/H 的“仅16:9、首验必须1920×1080”作窄例外：Mac 可在已验证原生 16:10 内容帧完成对应 gate；1920×1080 仍保留为既有16:9回归目标。仓库 AGENTS 的相同视觉条款按此修订解释。任意宽高比、完整任务覆盖仍不在本次承诺内。

## 替代方案

- 强制 AXSize：当前官方窗口不支持可写 AXSize，不继续重试。
- 改系统显示或虚拟显示：超出用户需求，且虚拟显示仍被禁止。
- 拉伸/中央裁切为16:9：会失真或丢失边缘 HUD，并破坏输入坐标，不采用。
- 一次性开放全部任务：缺乏页面布局证据，不采用。

## 安全、权限及兼容性

不增加权限、依赖、OS API、后台控制或输入路径。foreground、release_all、帧时效和 geometry generation 保护不变。尺寸改变仍使旧帧失效。未知比例明确拒绝；布局未经验证不提升任务状态。Windows 配置和默认坐标 helper 不变，新增行为显式选择，不能让截图宽高比全局改变所有 consumer。

## 测试与验收

覆盖16:9恒等/既有结果、16:10尺寸、非整数缩放、上下左右/中心锚点、OCR结果不二次转换、未知比例拒绝及 resize 失效。运行框架定向/全量与OK-WW导入和任务测试；本地Mac结果不冒充Windows runner。

新增真机证据需逐项记录：实际内容帧、scale、无标题栏、识别区域、点击命中、焦点/停止释放及代表性任务端到端。基础输入验收与页面视觉验收分开；任务仍 experimental，完成对应端到端才 validated。packaged app、权限撤销和公开发布门槛不变。

## 迁移、回滚与交付

不重写用户持久热键/游戏配置。开发仍为 sibling editable，发布需不可变框架版本。仅在本地长期集成分支提交，不 push/PR。回滚时先停止任务并释放输入，撤销 consumer 的16:10接入，再撤销框架新增行为；保留Windows16:9、原有安全修复和历史验收记录。任何相关回归重新打开证据门槛。

## 来源与许可证

依据用户截图、用户确认和本地公开API实测；不引入或复制第三方实现，不提交个人截图。

# macOS 原生 16:10 与 16:9 比例适配

2026-09-05；依照 ADR `decisions/0001-native-macos-aspect-ratio.md` 实施。当前为本地实验实现，不代表任务端到端或packaged app通过。

## 本轮范围确认（2026-09-06）

- 用户明确要求本轮正常适配 MacBook Pro 内屏常用的 16:10 与外接屏常用的 16:9，
  其他比例留待后续。以真实游戏内容比例决定适配，不以显示器名称推断。
- 1280×800 与 1920×1080 是当前真机验收点，不是硬编码的唯一分辨率。
  两类比例内继续使用现有最低 1280×720 与原生帧缩放/几何代际规则，
  不强制切屏幕、切全屏、改比例或伪造 1080p。
- 独立内部 probe 也按相同比例与最低尺寸规则检查，OCR 区域按原生宽度缩放；
  换屏后的新鲜尺寸由 capture 确認，非目标比例失败关闭。
- 两类比例分别记录任务、识别及输入证据；16:9 通过不等于 16:10 通过，反之亦然。
  当前最新事实见 `macos-internal-acceptance.md`，以下早期验证记录保留为历史。

## 行为

- Mac `supported_resolution` 使用 `allowed_ratios=['16:9','16:10']`，最低1280×720；`force_ratio=True`，未知比例启动检查失败。`ratio='16:9'`继续作为任务参考，而不是捕获目标。不自动resize窗口。
- 实际尺寸按新ScreenCaptureKit帧读取。菜单中1280×800、1352×845、1512×945仅是候选；不以菜单值或固定Retina倍数推断帧尺寸。1512×982不满足本次比例策略。
- `coordinate_mode='anchored'`：点与显式大小等比缩放，按左右/上下边缘或显式中心锚定；精确0.5位于真实中心。起止坐标定义的ROI分别映射两端，因此全屏/跨中心框覆盖真实画布。已有中心标记仍适用。
- `click_relative`、`box_of_screen`、直接OCR和Feature搜索ROI使用同一策略；显式像素Box、识别返回坐标不再次变换。Feature模板沿用已有等比缩放，不复制Mac素材，不拉伸整帧。
- Windows配置与legacy helper默认行为不变。不增加权限、依赖或后台路径，geometry变化仍使旧输入/帧失效。

## 限制

边缘锚点不是游戏所有页面布局的证明。中央弹窗、技能栏和复杂路线需逐页观察及显式中心锚点；未通过任务仍experimental/unsupported。直接自行计算像素的游戏代码不被此策略神奇地修正。本次不声明任意比例、所有菜单、OCR模型或完整战斗支持。

旧1080p smoke仍默认精确1920×1080。可通过 `scripts/smoke_macos_foreground_input.py --expected-frame-size 1280x800` 等明确选择原生目标（先以实际新帧核实尺寸），默认仅只读预检，不构造interaction。F2执行选项仍是旧诊断动作，不代表当前用户指南绑定；用户指南键为Y，不应执行F2来验证指南。

## 验证

- 新增16:9身份、16:10多尺寸/边缘/中心/ROI、模板等比、OCR/Feature接入、显式Box不二次映射、最小尺寸/未知比例和Windows配置隔离测试。
- 框架最终全量548 passed、12 skipped、4 subtests passed；OK-WW定向19 passed。独立审查复核通过。本轮只读取帧暂未枚举到游戏窗口，因此没有新增16:10真机证据；不提交用户截图。
- 下一步：取得可见游戏窗口的新原生帧，核实内容区、做只读识别与逐项输入命中，之后才更新Stage F及任务状态。完整Windows runner与packaged app仍未验收。

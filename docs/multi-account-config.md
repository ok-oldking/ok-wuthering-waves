# 多账号配置

左侧“多账号配置”页面提供独立于原“多账号每日任务”的执行入口。
旧任务及其配置不变。

1. 点击“新增账号”，填写登录列表账号文本去掉所有 `*` 后的剩余部分。
2. 选择执行任务，展开卡片编辑该账号的任务配置。
3. 点击“保存配置”，或点击“开始执行”自动保存后启动。

卡片右上角可切换账号是否启用，保存或开始执行时写入配置。旧配置默认启用。
停用账号不会登录或执行任务，也不会覆盖它已有的运行结果。
卡片显示上次运行结束时间：✓ 表示成功，✗ 表示失败或手动停止；鼠标悬停可查看详情。
未运行过的账号显示“未运行”。结果单独保存到 `MultiAccountResults.json`，重启后仍可查看，
保存账号配置不会覆盖运行记录。一次运行成功包含登录、任务执行和返回登录页完整流程。
展开卡片切换任务时会重新计算高度，并保持展开状态。

账号按卡片排列顺序执行，标识不得重复。手机号 `123****1234` 填 `1231234`，
邮箱 `Ab****12@outlook.com` 填 `Ab12@outlook.com`，显示名 `Some Name` 原样填写。
识别文本（ComboBox 或 OCR）删除所有 `*` 并去掉首尾空格，再与配置完整匹配；
保留大小写、内部空格和数字，不做模糊替换。旧七位数字配置继续有效。
所有账号需要已存在于游戏登录列表中。

本分支复用 PR #1701 的原生 ComboBox 读写函数，优先按配置选择并读回确认。
原生控件不存在、读写异常、目标缺失或选择确认失败时回退 OCR。
OCR 路径独立识别并确认目标账号，失败后才终止任务；用户主动停止时不回退。
OCR 支持带任意数量星号的账号、邮箱和当前配置的无掩码目标；界面文本必须能被完整识别。
国服原生控件结构及真实游戏效果仍需实机验证。
如果列表中找不到目标账号、账号确认不一致或任务失败，执行器会停止，状态区保留结果。
可先把任务选成“无”验证切号；它仍会登录账号，再返回登录页处理下一账号。

任务下拉取自 executor 已注册且在“任务”页可见的 `src.task` 一次性任务，
不包含实时触发任务或隐藏 runner。旧多账号任务会显示，但保存和执行时禁止选择，
以免嵌套切号；新 runner 同样受递归保护。原配置若绑定了已不可用的任务，需重新选择。

OCR 识别到多行相同目标账号时，点击屏幕中位置最靠下的一行，并在登录前再次确认账号。
日志卡片位于账号配置上方，运行前隐藏，开始运行后显示任务页同款信息表、状态和耗时。
运行结束后保留结果供检查；可手动关闭，下次运行重新显示。

Windows 的 PostMessage 模式下，登录阶段会先把真实鼠标移动到点击位置，
等待 0.2 秒后再发送后台点击消息，以兼容依赖真实鼠标悬停的登录按钮。
账号确认后的登录点击和等待登录中的重试均适用；完成或取消后恢复普通后台点击。

每张卡片复用框架 `ConfigContentMixin`（与 `ConfigCard` 相同的配置控件、说明及子配置规则）。
首次选择任务时复制普通任务的当前配置；后续加载时以账号保存的值覆盖当前配置，
新增字段继承当前普通任务配置。页面中的“重置配置”只重置该账号的内存配置。

数据保存在 executor 配置目录的 `MultiAccountConfig.json`，默认目录是 `configs`。
真实账号标识与独立任务配置只存放在本地 JSON，不要写入 Python 源码。
`configs/` 已被 Git 忽略，账号配置和 `MultiAccountResults.json` 运行记录均不提交。
本地示例 `configs/MultiAccountConfig.example.json` 使用虚构的 `1231234`，并默认停用。
示例数字仅为占位，请按游戏实际显示文本填写。
任务使用模块名和类名标识，因此改变显示语言不会丢失绑定。
任务被移除时会显示“任务不可用”，需要重新选择后才能保存。

日志表格按值的内容换行并自动调整行高和卡片高度，窗口宽度变化时重新计算。
账号卡片从顶部开始依次紧凑排列；日志过长时使用页面滚动查看。

执行由框架 start controller 调度，Qt 主线程不执行切号或 OCR。
每个账号运行期间，已注册任务的 `config` 临时替换为内存副本，避免子任务调用间接写回配置；
选中的任务再叠加当前账号配置。正常结束、异常和取消均通过 `finally` 恢复原配置对象。
这不隔离游戏操作、全局配置或任务自行写入的其他业务文件。

回归测试（无需连接游戏）：

```powershell
.\.venv\Scripts\python.exe -m unittest tests.TestMultiAccountConfig tests.TestMultiAccountDailyTask tests.TestScheduleSupport
```

真实游戏验收建议使用三个已登录过的账号，依次配置任务 A、无、任务 B，
检查切号顺序、任务参数、最终登录页和状态区，同时核对原任务配置文件内容未发生变化。

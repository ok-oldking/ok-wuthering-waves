# Review GitHub issues

Use `ok-oldking/ok-wuthering-waves`. When no issue number is given, scan the open issues and prioritize reports awaiting a useful reply or with new evidence. Read the issue and its comments before replying. Use the reporter's language and avoid repeating requests already made.

Every bug report requires the reporter to use **Export Logs** (「导出日志」) in OK-WW and attach the generated `OK-WW-log.zip` directly to the GitHub issue or a follow-up comment. Log snippets, individual log files, and screenshots are supplemental. If the app cannot open, ask what blocks the export and request available startup diagnostics while the export is pending. Questions and feature requests do not require the ZIP.

Use the **Ground your analysis** guidance in [issue-triage.md](../../../.github/workflows/issue-triage.md) for checking attachments, releases, code, and related issues. The workflow's labeling, assignment, and closure steps apply to that workflow. For a manual review-and-reply request, post comments only unless the user authorizes other issue changes.

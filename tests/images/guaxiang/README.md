# 卦象识别样本与验收

`manifest.json` 记录全部 11 张用户原始截图的路径、预期序列、附件名及
SHA-256。原图按字节复制，未去除红框、改变颜色或压缩尺寸。

两个模板来源图保存在 `assets/images/douling_gua_blue.png` 和
`assets/images/douling_gua_yellow.png`，其余九张在本目录。
COCO 标签为 `douling_gua_blue`、`douling_gua_yellow`，两处真实主体标注均为
1600×900 参考画面中的 `[782, 746, 21, 27]`。

| 样本 | 预期序列 | 用途 |
| --- | --- | --- |
| blue1_grass | 蓝 | 草地背景 |
| mixed4 | 黄、蓝、蓝、蓝 | 混合颜色与顺序，保留用户辅助红框 |
| blue4 | 蓝、蓝、蓝、蓝 | 弱光与强光圈 |
| blue3 | 蓝、蓝、蓝 | 数量变化 |
| blue2 | 蓝、蓝 | 明亮背景与连接光效 |
| empty | 空列表 | 无卦象负样本 |
| blue1 | 蓝 | 蓝色模板来源，自检 |
| yellow4 | 黄、黄、黄、黄 | 弱光与强光圈 |
| yellow1 | 黄 | 黄色模板来源，自检 |
| yellow2 | 黄、黄 | 强光圈与明亮背景 |
| yellow3 | 黄、黄、黄 | 明亮背景与数量变化 |

识别算法位于 `src/utils/guaxiang.py`，内置角色接入位于
`src/char/Douling.py`。每次 `do_perform()` 在执行对应段数之前进行一次
`entry` 识别，只记录结果，不影响该段执行。完整队伍加载后，
`configs/custom_teams/<队伍名>/Douling.py` 如果存在，可能覆盖内置角色实现，
验收时应确认实际加载的代码。

第二段跳跃及落地处理之后，进入重击前的四卦象门控：

- 首轮立即刷新并识别，期限内确认四个卦象就返回成功，继续原有
  2.5 秒重击、声骸、大招及切人。
- 不足四个或结果不确定时，首次允许立即普攻；后续普攻从上一次输入
  完成后至少等待 0.3 秒，慢帧不补发积压普攻。
- 相邻识别轮询开始时间至少间隔 0.1 秒，本轮截图、识别及输入耗时
  从等待时间中扣除。识别不再绑定普攻后的固定 0.3 秒睡眠。
- 使用单调时钟限制等待：3 秒或 30 次尝试，任一达到即失败；空帧也计入
  尝试次数。最后一次失败尝试不追加普攻。失败时重置到第一段并切人，
  跳过本段重击、声骸及大招，不重复开头的 E 或跳跃。
- 截图及识别完成后再次检查期限，超时得到四个也不放行。主动睡眠不超过
  剩余期限，但底层采集、识别或输入调用不能被此循环强制中断，实际退出
  时间仍可能晚于 3 秒。退战和手动停止任务继续通过异常中断循环。

日志仅保留以下输出，不保存卦象截图、不绘框、不逐轮输出卦象识别或补卦动作：

- `[DoulingRecognition] point=entry`：确定时输出 `count` 和 `sequence`，
  不确定时输出 `status=uncertain` 与 `reason`。
- `[DoulingGuaxiang] action=continue_to_heavy`：成功汇总，包含四卦象序列、
  `attempts` 和 `elapsed`。
- `[DoulingGuaxiang] action=abort`：失败汇总，包含 `reason=timeout|max_attempts`、
  `attempts`、`elapsed` 和最后一次 `count`。
- 识别异常记录 WARNING，每个门控等待周期最多一次；失败汇总另计。

无候选且调用方确认 HUD 有效时返回 `[]`；隐藏 HUD、无效截图、缺失资源、
弱匹配、颜色冲突或超过四个候选返回 `None`。这不保证所有未知场景都能检测
出漏检或遮挡，需要继续通过真实截图和实战验证。当前仍为单帧四卦象放行，
本次轮询调整不改变模板、阈值、颜色规则及整帧复制方式。

运行测试时优先使用仓库 `.venv` 的 Python：

```powershell
.\.venv\Scripts\python.exe -B -m unittest tests.TestGuaxiang tests.TestDouling tests.TestCustomCharLoader -v
```

仅在不存在本地虚拟环境解释器时，将上述解释器替换为 `python`。
测试覆盖原图、人工缩放、人工宽屏居中、区域内平移、错误颜色、重复候选、
五个符文、无效输入、真实队伍 HUD 模板，以及内置角色的两段执行与失败分支。
内置角色测试不依赖本地自定义队伍文件。模拟时钟测试覆盖立即成功、0.1 秒
补满、普攻限频、慢采集/识别/输入、剩余期限睡眠、次数限制及任务中断；
这些结果不能代替实机的截图采集和操作响应验证。

全部 11 张原图中，两张为模板来源自检、九张为其他截图回归；其他截图也
参与了方案调试，因此这不是独立盲测集。人工缩放至 720p、1080p、1440p 和
人工加宽只能验证坐标/插值，不能代替对应分辨率、UI 缩放及动画状态的实机验证。

历史开发环境曾测得缓存后纯识别约 0.6 ms，首次解码模板原图约 71 ms；
这些是特定环境的历史数据，不是性能保证，也不包括游戏截图采集与 HUD 检查。
性能对比应在同一环境、同一组 11 张原图上预热模板后重复测量，分别报告
平均值、P95 和最大值，并注明调用次数。轮询优化主要减少等待期间的发现延迟，
没有优化纯识别算法。理论上的轮询等待由接近 300 ms 降至接近 100 ms，
实际还受采集、HUD 检查、输入和调度耗时影响。识别及 HUD 检查频率可能提高到
原来的约三倍，实机验收应对比响应时间和 CPU 占用。
